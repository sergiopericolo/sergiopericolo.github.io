[A] The Rod Cutting Problem

[i] Serling Enterprises case

Serling Enterprises buys long steel rods of length \(n\) and cuts them into shorter rods, which it then sells.

  • The shorter rods may take any integer length \(j = 1, 2, \dots, n\)
  • A rod of length \(j\) is sold at a price \(p_{j}\)
  • Each cut is free

Serling Enterprises wants to know the best way to cut up the long rods. We may call this the Rod Cutting Problem (RCP).

For example, let \(n = 4\) and let the prices be defined as follows:

\(j\) 1 2 3 4
\(p_{j}\) 1 5 8 9

Questions:

  • In how many ways can we cut a rod of length 4?
  • In this specific case, what is the maximum profit cutting pattern?

Possible solutions (cutting patterns) when \(n = 4\):

Pattern A Pattern B
(++++) = 9 (+)(+++) = 1 + 8 = 9
(++)(++) = 5 + 5 = 10 (+++)(+) = 8 + 1 = 9
(+)(+)(++) = 1 + 1 + 5 = 7 (+)(++)(+) = 1 + 5 + 1 = 7
(++)(+)(+) = 5 + 1 + 1 = 7 (+)(+)(+)(+) = 1 + 1 + 1 + 1 = 4

[ii] Recursive formula (RCP)

The search for an optimal solution can be set as a recursion:

\[r_{n} = \max \{ p_{n}, r_{1} + r_{n-1}, r_{2} + r_{n-2}, \dots, r_{n-1} + r_{1} \}\]

In other words, once we decide where to put the first cut, we have divided the problem into two subproblems, that can be solved using the same logic until a trivial problem \(r_{1}\) is reached.

Optimal Substructure: Optimal solutions to a problem incorporate optimal solutions to related subproblems, which we may solve independently.

An equivalent, but simpler, recursion is the following:

\[r_{n} = \max_{1 \le j \le n} \{ p_{j} + r_{n-j} \} = \max \{ p_{1} + r_{n-1}; p_{2} + r_{n-2}; \dots; p_{n} + r_{0} \}\]

Here, we decide the length \(j\) of the first piece to be cut off on the left (and no further cut), and then we call recursively for the optimal decomposition of the piece of length \(n-j\) on the right.

We can understand how the recursion works by setting \(n=4\):

  • \(r_{4} = \max \{ p_{1} + r_{3}; p_{2} + r_{2}; p_{3} + r_{1}; p_{4} + r_{0} \}\)
  • \(r_{3} = \max \{ p_{1} + r_{2}; p_{2} + r_{1}; p_{3} + r_{0} \}\)
  • \(r_{2} = \max \{ p_{1} + r_{1}; p_{2} + r_{0} \}\)
  • \(r_{1} = p_{1} + r_{0}\)
  • \(r_{0} = 0\)

To compute \(r_{n}\) efficiently, it is convenient to compute all values of \(r_{j}\) for all \(j = 0, 1, \dots, n\) and for increasing values of \(j\). In this way, every value \(r_{j}\) (i.e., every subproblem) is computed (solved) only once.

Algorithm (Profit Calculation):

  • Step [1]: Initialize \(r = [r_{0}, r_{1}, \dots, r_{n-1}, r_{n}]\). Set \(r_{0} = 0\) and \(j = 1\).
  • Step [2]: Compute \(r_{j} = \max \{ p_{1} + r_{j-1}; p_{2} + r_{j-2}; \dots; p_{j} + r_{0} \}\). Set \(j = j + 1\).
  • Step [3]: if \(j > n\) then return \(r_{n}\) and STOP; else go to Step [2].

[iii] Dynamic Programming for the RCP

The above algorithm finds the optimal profit, but it doesn't save the corresponding solution. To save the solution, we need another array \(s = [s_{0}, s_{1}, s_{2}, \dots, s_{n}]\).

For all \(j = 0, 1, 2, \dots, n\), entry \(s_{j}\) will be the size of the first piece cut from a rod of total length \(j\) to get the optimal profit.

Solution reconstruction:

  • Let \(n = 5\) and let \(s = [0, 1, 2, 3, 2, 2]\)
  • \(s_{5} = 2 \implies\) a piece of length 2 must be cut; it remains a rod of length 3
  • \(s_{3} = 3 \implies\) a piece of length 3 must be cut; it remains a rod of length 0
  • We are done.

Revised Algorithm (with Solution Reconstruction):

  • Step [1]: Initialize \(r = [r_{0}, r_{1}, \dots, r_{n}]\) and \(s = [s_{0}, s_{1}, \dots, s_{n}]\). Set \(r_{0} = 0\) and \(j = 1\).
  • Step [2]:
    • Compute \(r_{j} = \max \{ p_{1} + r_{j-1}; p_{2} + r_{j-2}; \dots; p_{j} + r_{0} \}\)
    • Let \(i \in \{1, 2, \dots, j\}\) be such that \(r_{j} = p_{i} + r_{j-i}\)
    • Set \(s_{j} = i\)
    • Set \(j = j + 1\)
  • Step [3]: if \(j > n\) then return \(r_{n}\) and \(s\) and STOP; else go to Step [2].

EXERCISE 2: Recursion for the RCP (Notes space)

Running Time (RCP)

Most of the work is done in Step 2. Step 2 sums \(j\) pairs of numbers and executes a fixed number of additional elementary operations. Thus, the number of operations executed is proportional to:

  • \(1\) when \(j=1\)
  • \(2\) when \(j=2\)
  • \(\dots\)
  • \(n\) when \(j=n\)

The total number of operations is proportional to:

\[1 + 2 + 3 + \dots + n = \frac{1}{2}n(n+1) = O(n^{2})\]

The running time is \(O(n^{2})\).

[B] The Knapsack Problem (KP)

[i] Paul Atreides' problem

Paul Atreides must choose a few items to survive in the deadly desert of Arrakis (tent, water flask, food, ...). He has only a small bag and a few minutes before the Sardaukar arrive. Each item has a volume and a survival value; the bag has a capacity of 5 liters and cannot hold everything. How should Paul fill the bag to maximize the total survival value?

Data:

  • Let \(j = 1, \dots, n\) be the available items
  • Let \(p_{j}\) be the value of item \(j\), and let \(v_{j}\) be its volume \((j = 1, \dots, n)\)
  • Let \(C\) be the capacity of Paul's bag

Variables:

  • Let \(x_{j} = 1\) if item \(j\) is chosen, \(x_{j} = 0\) otherwise \((j = 1, \dots, n)\)

Model:

\[\max \sum_{j=1}^{n} p_{j}x_{j}\]

\[\text{s.t. } \sum_{j=1}^{n} v_{j}x_{j} \le C\]

\[x_{j} \in \{0, 1\} \quad \text{for all } j = 1, \dots, n\]

Assume Paul must choose among four items. Their values and volumes are as follows:

\(j\) 1 2 3 4
\(p_{j}\) 3 4 5 6
\(v_{j}\) 2 3 4 5

Paul's problem can be formulated as:

\[\max 3x_{1} + 4x_{2} + 5x_{3} + 6x_{4}\]

\[\text{s.t. } 2x_{1} + 3x_{2} + 4x_{3} + 5x_{4} \le 5\]

\[x_{j} \in \{0, 1\} \quad (j = 1, \dots, 4)\]

As the Rod Cutting Problem (RCP), the Knapsack Problem (KP) has an optimal substructure: optimal solutions to a problem incorporate optimal solutions to related subproblems, which we may solve independently.

Differences between RCP and KP:

Rod Cutting Problem (RCP) Knapsack Problem (KP)
\(v_{j} = j = 1, 2, \dots, n\) \(v_{j}\)'s are specific integers
We can cut any number of pieces of length \(j\) Every item \(j\) can be loaded at most once
  • The first difference simplifies things in RCP.
  • The second difference makes things more complicated in KP.

[ii] Subproblems and Recursive formula (KP)

The subproblems of a Knapsack Problem are obtained considering fewer item types and/or smaller knapsack capacity. For each pair of integers \(j, g\) with \(0 \le j \le n\) and \(0 \le g \le C\), let:

\[f(g, j) = \max \sum_{i=1}^{j} p_{i}x_{i}\]

\[\text{s.t. } \sum_{i=1}^{j} v_{i}x_{i} \le g\]

\[x_{i} \in \{0, 1\} \quad \text{for all } i = 1, \dots, j\]

The original problem is \(f(C, n)\).

The subproblems can be solved by the following recursion:

\[f(g, j) = \begin{cases} \max \{ p_{j} + f(g - v_{j}, j - 1), f(g, j - 1) \} & \text{if } g - v_{j} \ge 0 \\ f(g, j - 1) & \text{otherwise} \end{cases}\]

  • \(p_{j} + f(g - v_{j}, j - 1) \rightarrow\) Item \(j\) is selected
  • \(f(g, j - 1) \rightarrow\) Item \(j\) is not selected

Initial conditions:

  • \(f(g, 0) = 0\) for all \(g = 0, 1, \dots, C\)
  • \(f(0, j) = 0\) for all \(j = 0, 1, \dots, n\)

[iii] Dynamic Programming for the KP

Every time the iteration step is run:

  • Condition A: if \(f(g, j) = p_{j} + f(g - v_{j}, j - 1)\) \(\implies\) item \(j\) is included in the solution (we MARK entry \(f(g, j)\)).
  • Condition B: if \(f(g, j) > p_{j} + f(g - v_{j}, j - 1)\) \(\implies\) item \(j\) is not included.

DP Algorithm (Forward Phase):

  • Step [1] (Initialization):
    • Initialize \(f = [f(g, j): 0 \le g \le C, 0 \le j \le n]\)
    • Set \(f(g, 0) = 0\) for all \(g = 0, 1, \dots, C\) and \(f(0, j) = 0\) for all \(j = 1, 2, \dots, n\)
    • Set \(j = 1\) and \(g = 1\)
  • Step [2] (Iteration):
    • if \(g - v_{j} \ge 0\) then \(f(g, j) = \max \{ p_{j} + f(g - v_{j}, j - 1); f(g, j - 1) \}\). If \(f(g, j) = p_{j} + f(g - v_{j}, j - 1)\), MARK \(f(g, j)\).
    • else \(f(g, j) = f(g, j - 1)\)
    • Set \(g = g + 1\)
  • Step [3] (End of column \(j\)):
    • if \(g \le C\) then go to Step [2]
    • else set \(j = j + 1\) and continue
  • Step [4] (End of all columns):
    • if \(j \le n\) then set \(g = 1\) and go to Step [2]
    • else return \(f(C, n)\) and STOP

The computations can be arranged on a table of dimensions \((C + 1) \times (n + 1)\):

\(f(g,j)\) 0 \(\dots\) \(j-1\) \(j\) \(\dots\)
0 0 \(\dots\) 0 0 \(\dots\)
\(\vdots\) \(\vdots\)
\(g - v_{j}\) 0 \(\dots\) \(f(g - v_{j}, j - 1)\) [2] \(\dots\)
\(\vdots\) \(\vdots\)
\(g\) 0 \(\dots\) \(f(g, j - 1)\) [3] \(f(g, j)\) [1] \(\dots\)

Where [1] \(= \max \{ p_{j} +\) [2] \(;\) [3] \(\}\).

Reconstructing a Solution (Backward Phase)

In the end, the bottom-right corner of the DP table contains \(f(C, n)\), i.e., the optimal knapsack value. The following procedure reconstructs the optimal subset \(S\) of items using the marked entries:

  • Step [5] (Initialization): Set \(g = C\), \(j = n\), and \(S = \emptyset\).
  • Step [6] (Termination): if \(g = 0\) or \(j = 0\) then return \(S\) and STOP; else continue.
  • Step [7] (Iteration): if \(f(g, j)\) is marked then set \(S = S \cup \{j\}\) and \(g = g - v_{j}\); else continue.
  • Step [8] (Column update): Set \(j = j - 1\) and go to Step [6].

Running Time and Observations (KP)

  • Step 1: Creates an array with \((C + 1) \times (n + 1)\) entries.
  • Step 2 - Step 4: Fixed number of elementary operations executed \(n \times C\) times.
  • Step 5 - Step 8: Fixed number of elementary operations executed at most \(n + C\) times.

The total number of elementary operations is proportional to \(C \times n\). The running time of the algorithm is \(O(nC)\), which in general is not polynomial in the input size (pseudopolynomial).

Observation: By construction, when solving a KP instance with \(n\) items and capacity \(C\) using Dynamic Programming, we simultaneously solve all instances with the first \(j\) items and capacity \(g\) where \(0 \le j \le n\) and \(0 \le g \le C\).

Conclusion

Solving a KP with \(n\) items and capacity \(C\) using Dynamic Programming requires:

  • Building a matrix with \(C + 1\) rows and \(n + 1\) columns
  • Performing a constant number of elementary operations for each cell
  • Time complexity: Pseudopolynomial \(O(nC)\)

The Knapsack Problem remains computationally hard in general, which explains the importance of heuristic approaches. Dynamic Programming is a general algorithmic idea that can be applied to many problems, including stochastic ones.

Manifesto of Monochrome Typographic Architecture

Designing a technical editorial system requires the systematic subtraction of every superfluous decorative element. When color is removed from the visual equation, the information hierarchy must rest exclusively on geometric proportion, on the luminous contrast between ink and surface, and on the structural tension between solids and voids. This first paragraph shows how text, kept at a small size and with very tight leading, forms a compact, dense rectangle on ivory paper, recalling the aesthetics of twentieth-century Swiss engineering manuals.

Breaking the line in the Markdown source produces a clean spatial caesura. The vertical void between this block and the previous one is not a simple margin, but a deliberate cognitive pause that separates two distinct logical units (just like in a Zettelkasten[01] system). Within the textual fabric, the eye immediately tells high-contrast structural emphasis apart from the thinner editorial italic, just as it recognizes inline technical elements such as the command gotomark --build --strict or the key sequence Ctrl + W + v, without ever breaking the horizontal rhythm of reading.

02. Code Monolith and Neovim Syntax (H2 Light 300)

The following block tests the deliberate integration of your Ghostty / Neovim palette within the ivory document. Notice how comments are dark but bold (color4 + bold), keywords and booleans shine in pure white (white + bold), functions and numbers stand out through brightness without bold, while strings, types and operators spread over the intermediate slate-gray tones (color1, color2, color3).

package engine

import (
	"bytes"
	"context"
	"fmt"
	"regexp"
)

// MaxDepth defines the recursion limit of the Zettelkasten tree
const MaxDepth int = 64

var validSlugRegex = regexp.MustCompile(`^[a-z0-9]+(?:-[a-z0-9]+)*$`)

// DocumentNode represents a single atomic unit of knowledge
type DocumentNode struct {
	ID       string            `json:"id"`
	Title    string            `json:"title"`
	RawBytes []byte            `json:"-"`
	Metadata map[string]string `json:"meta"`
	Published bool             `json:"published"`
	Weight   float64           `json:"weight"`
}

// Compile turns the Markdown node into a minimal HTML fragment
func (n *DocumentNode) Compile(ctx context.Context, strictMode bool) (string, error) {
	if !n.Published && strictMode {
		return "", fmt.Errorf("compile aborted: node %q is unpublished\n", n.ID)
	}

	var buf bytes.Buffer
	const headerTpl = "<article data-node=\"%s\" data-weight=\"%.2f\">\n"

	for idx := 0; idx < len(n.RawBytes); idx++ {
		b := n.RawBytes[idx]
		if b == 0x00 {
			continue
		}
		buf.WriteByte(b)
	}

	result := fmt.Sprintf(headerTpl, n.ID, 1.05) + buf.String() + "\n</article>"
	return result, nil
}
