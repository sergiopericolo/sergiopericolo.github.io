[A] Il problema del taglio delle barre

[i] Il caso Serling Enterprises

Serling Enterprises acquista lunghe barre d'acciaio di lunghezza \(n\) e le taglia in barre più corte, che poi rivende.

  • Le barre più corte possono avere qualsiasi lunghezza intera \(j = 1, 2, \dots, n\)
  • Una barra di lunghezza \(j\) viene venduta al prezzo \(p_{j}\)
  • Ogni taglio è gratuito

Serling Enterprises vuole sapere qual è il modo migliore di tagliare le barre lunghe. Chiamiamo questo problema Rod Cutting Problem (RCP), il problema del taglio delle barre.

Ad esempio, sia \(n = 4\) e siano i prezzi definiti come segue:

\(j\) 1 2 3 4
\(p_{j}\) 1 5 8 9

Domande:

  • In quanti modi possiamo tagliare una barra di lunghezza 4?
  • In questo caso specifico, qual è lo schema di taglio di profitto massimo?

Soluzioni possibili (schemi di taglio) quando \(n = 4\):

Schema A Schema B
(++++) = 9 (+)(+++) = 1 + 8 = 9
(++)(++) = 5 + 5 = 10 (+++)(+) = 8 + 1 = 9
(+)(+)(++) = 1 + 1 + 5 = 7 (+)(++)(+) = 1 + 5 + 1 = 7
(++)(+)(+) = 5 + 1 + 1 = 7 (+)(+)(+)(+) = 1 + 1 + 1 + 1 = 4

[ii] Formula ricorsiva (RCP)

La ricerca di una soluzione ottima può essere impostata come una ricorsione:

\[r_{n} = \max \{ p_{n}, r_{1} + r_{n-1}, r_{2} + r_{n-2}, \dots, r_{n-1} + r_{1} \}\]

In altre parole, una volta deciso dove fare il primo taglio, abbiamo diviso il problema in due sottoproblemi, che possono essere risolti con la stessa logica fino a raggiungere un problema banale \(r_{1}\).

Sottostruttura ottima: le soluzioni ottime di un problema contengono le soluzioni ottime di sottoproblemi correlati, che possiamo risolvere in modo indipendente.

Una ricorsione equivalente, ma più semplice, è la seguente:

\[r_{n} = \max_{1 \le j \le n} \{ p_{j} + r_{n-j} \} = \max \{ p_{1} + r_{n-1}; p_{2} + r_{n-2}; \dots; p_{n} + r_{0} \}\]

Qui decidiamo la lunghezza \(j\) del primo pezzo da tagliare a sinistra (senza ulteriori tagli), e poi richiamiamo ricorsivamente la scomposizione ottima del pezzo di lunghezza \(n-j\) a destra.

Possiamo capire come funziona la ricorsione ponendo \(n=4\):

  • \(r_{4} = \max \{ p_{1} + r_{3}; p_{2} + r_{2}; p_{3} + r_{1}; p_{4} + r_{0} \}\)
  • \(r_{3} = \max \{ p_{1} + r_{2}; p_{2} + r_{1}; p_{3} + r_{0} \}\)
  • \(r_{2} = \max \{ p_{1} + r_{1}; p_{2} + r_{0} \}\)
  • \(r_{1} = p_{1} + r_{0}\)
  • \(r_{0} = 0\)

Per calcolare \(r_{n}\) in modo efficiente conviene calcolare tutti i valori \(r_{j}\) per ogni \(j = 0, 1, \dots, n\), in ordine crescente di \(j\). In questo modo ogni valore \(r_{j}\) (cioè ogni sottoproblema) viene calcolato (risolto) una sola volta.

Algoritmo (calcolo del profitto):

  • Passo [1]: Inizializza \(r = [r_{0}, r_{1}, \dots, r_{n-1}, r_{n}]\). Poni \(r_{0} = 0\) e \(j = 1\).
  • Passo [2]: Calcola \(r_{j} = \max \{ p_{1} + r_{j-1}; p_{2} + r_{j-2}; \dots; p_{j} + r_{0} \}\). Poni \(j = j + 1\).
  • Passo [3]: if \(j > n\) then restituisci \(r_{n}\) e STOP; else vai al Passo [2].

ESERCIZIO 1: Ricorsione per l'RCP (spazio per gli appunti)

[iii] Programmazione dinamica per l'RCP

L'algoritmo precedente trova il profitto ottimo, ma non salva la soluzione corrispondente. Per salvarla serve un secondo vettore \(s = [s_{0}, s_{1}, s_{2}, \dots, s_{n}]\).

Per ogni \(j = 0, 1, 2, \dots, n\), l'elemento \(s_{j}\) sarà la lunghezza del primo pezzo tagliato da una barra di lunghezza totale \(j\) per ottenere il profitto ottimo.

Ricostruzione della soluzione:

  • Sia \(n = 5\) e sia \(s = [0, 1, 2, 3, 2, 2]\)
  • \(s_{5} = 2 \implies\) va tagliato un pezzo di lunghezza 2; resta una barra di lunghezza 3
  • \(s_{3} = 3 \implies\) va tagliato un pezzo di lunghezza 3; resta una barra di lunghezza 0
  • Abbiamo finito.

Algoritmo rivisto (con ricostruzione della soluzione):

  • Passo [1]: Inizializza \(r = [r_{0}, r_{1}, \dots, r_{n}]\) e \(s = [s_{0}, s_{1}, \dots, s_{n}]\). Poni \(r_{0} = 0\) e \(j = 1\).
  • Passo [2]:
    • Calcola \(r_{j} = \max \{ p_{1} + r_{j-1}; p_{2} + r_{j-2}; \dots; p_{j} + r_{0} \}\)
    • Sia \(i \in \{1, 2, \dots, j\}\) tale che \(r_{j} = p_{i} + r_{j-i}\)
    • Poni \(s_{j} = i\)
    • Poni \(j = j + 1\)
  • Passo [3]: if \(j > n\) then restituisci \(r_{n}\) e \(s\) e STOP; else vai al Passo [2].

ESERCIZIO 2: Ricorsione per l'RCP (spazio per gli appunti)

Tempo di esecuzione (RCP)

La maggior parte del lavoro avviene nel Passo 2. Il Passo 2 somma \(j\) coppie di numeri ed esegue un numero fisso di operazioni elementari aggiuntive. Il numero di operazioni eseguite è quindi proporzionale a:

  • \(1\) quando \(j=1\)
  • \(2\) quando \(j=2\)
  • \(\dots\)
  • \(n\) quando \(j=n\)

Il numero totale di operazioni è proporzionale a:

\[1 + 2 + 3 + \dots + n = \frac{1}{2}n(n+1) = O(n^{2})\]

Il tempo di esecuzione è \(O(n^{2})\).

[B] Il problema dello zaino (KP)

[i] Il problema di Paul Atreides

Paul Atreides deve scegliere alcuni oggetti per sopravvivere nel deserto letale di Arrakis (tenda, borraccia, cibo, ...). Ha solo una piccola borsa e pochi minuti prima che arrivino i Sardaukar. Ogni oggetto ha un volume e un valore di sopravvivenza; la borsa ha una capacità di 5 litri e non può contenere tutto. Come dovrebbe riempire la borsa Paul per massimizzare il valore di sopravvivenza totale?

Dati:

  • Siano \(j = 1, \dots, n\) gli oggetti disponibili
  • Sia \(p_{j}\) il valore dell'oggetto \(j\) e sia \(v_{j}\) il suo volume \((j = 1, \dots, n)\)
  • Sia \(C\) la capacità della borsa di Paul

Variabili:

  • Sia \(x_{j} = 1\) se l'oggetto \(j\) viene scelto, \(x_{j} = 0\) altrimenti \((j = 1, \dots, n)\)

Modello:

\[\max \sum_{j=1}^{n} p_{j}x_{j}\]

\[\text{s.t. } \sum_{j=1}^{n} v_{j}x_{j} \le C\]

\[x_{j} \in \{0, 1\} \quad \text{per ogni } j = 1, \dots, n\]

Supponiamo che Paul debba scegliere tra quattro oggetti, con i seguenti valori e volumi:

\(j\) 1 2 3 4
\(p_{j}\) 3 4 5 6
\(v_{j}\) 2 3 4 5

Il problema di Paul può essere formulato come:

\[\max 3x_{1} + 4x_{2} + 5x_{3} + 6x_{4}\]

\[\text{s.t. } 2x_{1} + 3x_{2} + 4x_{3} + 5x_{4} \le 5\]

\[x_{j} \in \{0, 1\} \quad (j = 1, \dots, 4)\]

Come il problema del taglio delle barre (RCP), anche il problema dello zaino (KP) ha una sottostruttura ottima: le soluzioni ottime di un problema contengono le soluzioni ottime di sottoproblemi correlati, che possiamo risolvere in modo indipendente.

Differenze tra RCP e KP:

Problema del taglio delle barre (RCP) Problema dello zaino (KP)
\(v_{j} = j = 1, 2, \dots, n\) i \(v_{j}\) sono interi specifici
Possiamo tagliare un numero qualsiasi di pezzi di lunghezza \(j\) Ogni oggetto \(j\) può essere caricato al massimo una volta
  • La prima differenza semplifica le cose nell'RCP.
  • La seconda differenza rende le cose più complicate nel KP.

[ii] Sottoproblemi e formula ricorsiva (KP)

I sottoproblemi di un problema dello zaino si ottengono considerando meno tipi di oggetti e/o una capacità minore dello zaino. Per ogni coppia di interi \(j, g\) con \(0 \le j \le n\) e \(0 \le g \le C\), sia:

\[f(g, j) = \max \sum_{i=1}^{j} p_{i}x_{i}\]

\[\text{s.t. } \sum_{i=1}^{j} v_{i}x_{i} \le g\]

\[x_{i} \in \{0, 1\} \quad \text{per ogni } i = 1, \dots, j\]

Il problema originale è \(f(C, n)\).

I sottoproblemi possono essere risolti con la seguente ricorsione:

\[f(g, j) = \begin{cases} \max \{ p_{j} + f(g - v_{j}, j - 1), f(g, j - 1) \} & \text{se } g - v_{j} \ge 0 \\ f(g, j - 1) & \text{altrimenti} \end{cases}\]

  • \(p_{j} + f(g - v_{j}, j - 1) \rightarrow\) l'oggetto \(j\) viene selezionato
  • \(f(g, j - 1) \rightarrow\) l'oggetto \(j\) non viene selezionato

Condizioni iniziali:

  • \(f(g, 0) = 0\) per ogni \(g = 0, 1, \dots, C\)
  • \(f(0, j) = 0\) per ogni \(j = 0, 1, \dots, n\)

[iii] Programmazione dinamica per il KP

Ogni volta che viene eseguito il passo di iterazione:

  • Condizione A: if \(f(g, j) = p_{j} + f(g - v_{j}, j - 1)\) \(\implies\) l'oggetto \(j\) è incluso nella soluzione (MARCHIAMO l'elemento \(f(g, j)\)).
  • Condizione B: if \(f(g, j) > p_{j} + f(g - v_{j}, j - 1)\) \(\implies\) l'oggetto \(j\) non è incluso.

Algoritmo DP (fase in avanti):

  • Passo [1] (Inizializzazione):
    • Inizializza \(f = [f(g, j): 0 \le g \le C, 0 \le j \le n]\)
    • Poni \(f(g, 0) = 0\) per ogni \(g = 0, 1, \dots, C\) e \(f(0, j) = 0\) per ogni \(j = 1, 2, \dots, n\)
    • Poni \(j = 1\) e \(g = 1\)
  • Passo [2] (Iterazione):
    • if \(g - v_{j} \ge 0\) then \(f(g, j) = \max \{ p_{j} + f(g - v_{j}, j - 1); f(g, j - 1) \}\). Se \(f(g, j) = p_{j} + f(g - v_{j}, j - 1)\), MARCA \(f(g, j)\).
    • else \(f(g, j) = f(g, j - 1)\)
    • Poni \(g = g + 1\)
  • Passo [3] (Fine della colonna \(j\)):
    • if \(g \le C\) then vai al Passo [2]
    • else poni \(j = j + 1\) e continua
  • Passo [4] (Fine di tutte le colonne):
    • if \(j \le n\) then poni \(g = 1\) e vai al Passo [2]
    • else restituisci \(f(C, n)\) e STOP

I calcoli possono essere organizzati in una tabella di dimensioni \((C + 1) \times (n + 1)\):

\(f(g,j)\) 0 \(\dots\) \(j-1\) \(j\) \(\dots\)
0 0 \(\dots\) 0 0 \(\dots\)
\(\vdots\) \(\vdots\)
\(g - v_{j}\) 0 \(\dots\) \(f(g - v_{j}, j - 1)\) [2] \(\dots\)
\(\vdots\) \(\vdots\)
\(g\) 0 \(\dots\) \(f(g, j - 1)\) [3] \(f(g, j)\) [1] \(\dots\)

Dove [1] \(= \max \{ p_{j} +\) [2] \(;\) [3] \(\}\).

Ricostruzione della soluzione (fase all'indietro)

Alla fine, l'angolo in basso a destra della tabella DP contiene \(f(C, n)\), cioè il valore ottimo dello zaino. La procedura seguente ricostruisce il sottoinsieme ottimo \(S\) di oggetti usando gli elementi marcati:

  • Passo [5] (Inizializzazione): Poni \(g = C\), \(j = n\) e \(S = \emptyset\).
  • Passo [6] (Terminazione): if \(g = 0\) oppure \(j = 0\) then restituisci \(S\) e STOP; else continua.
  • Passo [7] (Iterazione): if \(f(g, j)\) è marcato then poni \(S = S \cup \{j\}\) e \(g = g - v_{j}\); else continua.
  • Passo [8] (Aggiornamento colonna): Poni \(j = j - 1\) e vai al Passo [6].

Tempo di esecuzione e osservazioni (KP)

  • Passo 1: crea un vettore con \((C + 1) \times (n + 1)\) elementi.
  • Passi 2 - 4: numero fisso di operazioni elementari eseguite \(n \times C\) volte.
  • Passi 5 - 8: numero fisso di operazioni elementari eseguite al massimo \(n + C\) volte.

Il numero totale di operazioni elementari è proporzionale a \(C \times n\). Il tempo di esecuzione dell'algoritmo è \(O(nC)\), che in generale non è polinomiale nella dimensione dell'input (pseudopolinomiale).

Osservazione: per costruzione, quando risolviamo con la programmazione dinamica un'istanza del KP con \(n\) oggetti e capacità \(C\), risolviamo contemporaneamente tutte le istanze con i primi \(j\) oggetti e capacità \(g\), dove \(0 \le j \le n\) e \(0 \le g \le C\).

Conclusioni

Risolvere un KP con \(n\) oggetti e capacità \(C\) tramite la programmazione dinamica richiede di:

  • Costruire una matrice con \(C + 1\) righe e \(n + 1\) colonne
  • Eseguire un numero costante di operazioni elementari per ogni cella
  • Complessità temporale: pseudopolinomiale \(O(nC)\)

Il problema dello zaino resta in generale computazionalmente difficile, il che spiega l'importanza degli approcci euristici. La programmazione dinamica è un'idea algoritmica generale che può essere applicata a molti problemi, compresi quelli stocastici.

Manifesto dell'Architettura Tipografica Monocromatica

La progettazione di un sistema editoriale tecnico richiede la sottrazione sistematica di ogni elemento decorativo superfluo. Quando il colore viene eliminato dall'equazione visiva, la gerarchia dell'informazione deve reggersi esclusivamente sulla proporzione geometrica, sul contrasto luminoso tra inchiostro e superficie, e sulla tensione strutturale tra pieni e vuoti. Questo primo paragrafo dimostra come il testo, mantenuto a una dimensione ridotta e con un'interlinea estremamente serrata, formi un rettangolo compatto e denso sulla carta avorio, richiamando l'estetica dei manuali di ingegneria svizzeri del ventesimo secolo.

Andando a capo nel sorgente Markdown, si genera una cesura spaziale netta. Il vuoto verticale tra questo blocco e il precedente non è un semplice margine, ma una pausa cognitiva deliberata che separa due unità logiche distinte (proprio come in un sistema Zettelkasten[01]). All'interno del tessuto testuale, l'occhio distingue immediatamente l'enfasi strutturale ad alto contrasto rispetto al corsivo editoriale più sottile, così come riconosce gli elementi tecnici inline quali il comando gotomark --build --strict oppure la sequenza di tasti Ctrl + W + v senza mai interrompere il ritmo orizzontale della lettura.

02. Monolite Codice e Sintassi Neovim (H2 Light 300)

Il blocco seguente testa l'integrazione consapevole della tua palette Ghostty / Neovim all'interno del documento avorio. Osserva come i commenti siano scuri ma in grassetto (color4 + bold), le parole chiave e i booleani brillino in bianco puro (white + bold), le funzioni e i numeri emergano per luminosità senza grassetto, mentre stringhe, tipi e operatori si distribuiscano sui toni intermedi di grigio ardesia (color1, color2, color3).

// =========================================================================
// GOTOMARK ENGINE — Renderer Statica & Pipeline AST
// I commenti usano --code-c4 (#50545D) in BOLD, fedele al tuo init.lua
// =========================================================================

package engine

import (
	"bytes"
	"context"
	"fmt"
	"regexp"
)

// MaxDepth definisce il limite di ricorsione dell'albero Zettelkasten
const MaxDepth int = 64

var validSlugRegex = regexp.MustCompile(`^[a-z0-9]+(?:-[a-z0-9]+)*$`)

// DocumentNode rappresenta una singola unità atomica di conoscenza
type DocumentNode struct {
	ID       string            `json:"id"`
	Title    string            `json:"title"`
	RawBytes []byte            `json:"-"`
	Metadata map[string]string `json:"meta"`
	Published bool             `json:"published"`
	Weight   float64           `json:"weight"`
}

// Compile trasforma il nodo Markdown in un frammento HTML minimale
func (n *DocumentNode) Compile(ctx context.Context, strictMode bool) (string, error) {
	if !n.Published && strictMode {
		return "", fmt.Errorf("compile aborted: node %q is unpublished\n", n.ID)
	}

	var buf bytes.Buffer
	const headerTpl = "<article data-node=\"%s\" data-weight=\"%.2f\">\n"

	for idx := 0; idx < len(n.RawBytes); idx++ {
		b := n.RawBytes[idx]
		if b == 0x00 {
			continue
		}
		buf.WriteByte(b)
	}

	result := fmt.Sprintf(headerTpl, n.ID, 1.05) + buf.String() + "\n</article>"
	return result, nil
}
