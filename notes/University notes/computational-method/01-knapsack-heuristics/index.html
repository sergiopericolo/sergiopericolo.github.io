The Knapsack Problem: greedy heuristics and local search

Lecture 1 of Computational Methods (Carlo Filippi, University of Brescia). One truck, too many boxes, one question: which boxes go on board? The Knapsack Problem (KP) is the simplest of the "hard" optimization problems, and the perfect testbed to understand what heuristics are and how their quality is measured.

Roadmap:

  1. The Star Truck case — a real loading problem and the algorithm in use today.
  2. The Knapsack Problem — the integer linear programming model.
  3. Exact, approximate and heuristic methods — computing time, error, performance ratio.
  4. Greedy algorithms — the idea, the sorting criteria, the worst case and the improved version with a 1/2 guarantee.
  5. Local search — neighborhoods, swaps, local optima.

The Star Truck case

Star Truck is a carrier. Every week one truck leaves Seattle for San Francisco and, the day before, a manager decides which boxes to load.

  • The boxes are about as wide as the truck (≈ 220 cm out of 270 cm) and cannot be stacked.
  • So length is the only dimension that matters: loading the truck means lining boxes up along its 1200 cm.
  • Each box has a priority from 1 to 10 (urgency of the shipment, importance of the customer).

Today nine boxes are waiting:

Box 1 2 3 4 5 6 7 8 9
Length (cm) 330 360 140 400 310 220 330 360 350
Priority 3 8 5 8 3 2 6 7 7

Total length is 2800 cm > 1200 cm: only a subset can ship. The natural criterion is to maximize the sum of the priorities loaded.

The current algorithm sorts boxes by decreasing priority and loads them in that order while there is room: 2, 4, 8 (1120 cm, priority 23); the others do not fit in the remaining 80 cm.

Is this the best we can do? Try it: start from "greedy P" (the current algorithm), step through it, then click the boxes to build a better load, and compare with "optimum".

The optimum is 26 (for instance boxes 2, 3, 7, 9: 1180 cm): the current algorithm loses 3 priority points, more than 10%.

The Knapsack Problem (KP)

We are given \(n\) items and one bin (the knapsack). Each item has a profit and a volume; the knapsack has a capacity \(C\). Find the subset of items with total volume not larger than \(C\) and maximum total profit. Star Truck is a KP: profits are priorities, volumes and capacity are lengths.

Data. Items \(j = 1, \dots, n\); profit \(p_j\) and volume \(v_j\) of each item; capacity \(C\).

Variables. \(x_j = 1\) if item \(j\) is chosen, \(x_j = 0\) otherwise.

\[\max \sum_{j=1}^{n} p_j x_j \quad \text{s.t.} \quad \sum_{j=1}^{n} v_j x_j \le C, \qquad x_j \in \{0, 1\} \quad (j = 1, \dots, n)\]

  • It is the most basic integer linear programming (ILP) model and a basic discrete optimization problem.
  • The number of solutions explodes: brute force must test up to \(2^n\) subsets. With 9 boxes that is 512; with 60 boxes, more than \(10^{18}\).

Exact, approximate and heuristic methods

Method What it does
Exact Finds an optimal solution (or proves none exists)
Approximate / heuristic Looks for a good feasible solution (value not too far from the optimum) in a short time (acceptable in practice and much smaller than an exact method's)

Two things matter about a heuristic: computing time and error with respect to the optimum. They are studied in three ways:

Analysis How Use
Experimental Run the algorithm on many instances (random or real) and collect statistics on errors and times Easy and very useful in practice
Probabilistic Error and time as random variables, studied with probability theory Mostly theoretical, only for simple algorithms
Worst case Upper bounds on time and error in the worst possible scenario Informative but usually very pessimistic

Computing time. Worst-case analysis bounds the order of magnitude at which time grows with the instance size: \(O(n)\), \(O(n \log n)\), \(O(n^2)\)…

Error. Let \(I\) be an instance of problem \(P\), \(OPT(I)\) its optimal value and \(A(I)\) the value returned by algorithm \(A\). In a maximization problem \(A(I) \le OPT(I)\) and the performance ratio on \(I\) is \(A(I)/OPT(I) \le 1\). The worst-case ratio is

\[R_A = \inf_{I \in P} \left\{ \frac{A(I)}{OPT(I)} \right\}\]

where the infimum runs over all possible instances. The closer to 1, the better: \(R_A = 0.5\) means "never below half the optimum, whatever the instance".

Terminology.

  • Approximate methods: come with theoretical results (worst case, probabilistic analysis).
  • Heuristic methods: empirical analysis shows satisfactory practical performance.
  • Constructive (greedy) methods: build a solution through a simple scan of the data. Very efficient, limited effectiveness.
  • Local search methods: improve a given solution iteratively while possible. Efficient and quite effective.

Greedy algorithms

The idea: start from an empty solution and add elements one at a time, following a simple criterion based on an order fixed in advance. No backtracking: every decision is permanent. Hence the name greedy.

A classic example is Kruskal's algorithm for the minimum spanning tree. Given a graph \(G = (V, E)\) with edge costs \(c_e\):

  1. Sort the edges from cheapest to most expensive; \(T = \emptyset\).
  2. Take the first edge \(e\) of the list.
  3. If \(T \cup \{e\}\) has no cycle, \(T = T \cup \{e\}\); otherwise discard \(e\).
  4. If the list is empty return \(T\), otherwise go back to step 2.

Greedy methods are very fast, but guarantee optimality only for problems with a very specific structure, called a matroid (the minimum spanning tree has it). Elsewhere they can be used as heuristics, but the distance from the optimum may be large.

Greedy for the KP

Input: profits \(p_1, \dots, p_n\), volumes \(v_1, \dots, v_n\), capacity \(C\). Output: a feasible binary vector \(x\).

  1. Sort the items by a criterion; residual capacity \(R = C\).
  2. Take the first item \(j\) of the list.
  3. If \(v_j \le R\): \(x_j = 1\) and \(R = R - v_j\); otherwise \(x_j = 0\).
  4. If the list is empty return \(x\), otherwise go back to step 2.

The sorting criteria:

Criterion Order Idea
P Nonincreasing profit Most valuable items first
V Nondecreasing volume Smallest items first, to fit many
UP Nonincreasing unit profit: \(p_1/v_1 \ge p_2/v_2 \ge \dots\) Best "profit per centimetre" first

Simple criteria often produce ties. Refined versions: P/V (nonincreasing profit, ties go to the smallest volume) and V/P (nondecreasing volume, ties go to the largest profit). In the widget above try the three criteria: on Star Truck they give 23, 13 and 23, against an optimum of 26. Criterion V fills the truck with small but unimportant boxes.

Performance: fast but without guarantees

  • Efficiency: after sorting, \(O(n \log n)\), the scan is linear, \(O(n)\).
  • Effectiveness: on average criterion UP is the best, but the performance ratio can be arbitrarily small.

The instance that proves it has capacity \(C > 1\) and two items: item 1 with \(p_1 = 1, v_1 = 1\) and item 2 with \(p_2 = C - 1, v_2 = C\). Item 1 has unit profit 1, item 2 has \((C-1)/C < 1\): UP takes item 1, after which item 2 no longer fits. Greedy finds \(P^G = 1\), the optimum is \(P^* = C - 1\), and the ratio \(1/(C-1)\) goes to 0 as \(C\) grows. Here with \(C = 100\):

[["1", 1, 1], ["2", 100, 99]]

Improved greedy: at least half the optimum

The fix is simple. Run greedy UP (solution \(x^G\), profit \(P^G\)); let \(k\) be the first item that did not fit. Compare \(x^G\) with the solution holding \(k\) alone, and return the better one:

\[\text{if } P^G > p_k \text{ return } x^G, \text{ otherwise } \tilde x \text{ with } \tilde x_k = 1,\ \tilde x_j = 0 \ (j \ne k)\]

In the widget above press "UP + best item": the pathological instance is solved to optimality.

Claim. The performance ratio of the improved greedy is at least 0.5.

Why. Let \(\hat P\) be the optimal value of the linear relaxation, the same problem with \(0 \le x_j \le 1\) (items can be "cut"). The relaxation is solved exactly by the UP order: load whole items while they fit, then a fraction of item \(k\). So:

  1. \(P^* \le \hat P\): relaxing constraints cannot make the optimum worse.
  2. \(\hat P \le P^G + p_k\): the whole items of the relaxation are among those greedy took, and the fraction of \(k\) is worth less than \(p_k\).
  3. Hence \(P^* \le P^G + p_k \le 2 \max\{P^G, p_k\}\), that is \(\max\{P^G, p_k\} \ge P^*/2\).

Local search

Instead of building, we improve an existing solution.

  1. Let a feasible solution \(x^0\) be given (the current solution).
  2. Examine the set \(N(x^0)\) of solutions "close" to the current one.
  3. If some \(\hat x \in N(x^0)\) is "better than" \(x^0\), set \(x^0 = \hat x\) and go to step 1; otherwise return \(x^0\).

In a maximization problem "better" means "with a higher objective value". \(N(\cdot)\) is the neighborhood function: it defines which solutions are close under some metric.

  • With two continuous variables: the points within Euclidean distance \(r\), \(\;N(x) = \{y \in \mathbb R^2 : \sqrt{(y_1 - x_1)^2 + (y_2 - x_2)^2} \le r\}\).
  • With binary variables: the vectors that differ in at most \(k\) bits, \(\;N(x) = \{y \in \{0,1\}^n : \sum_i |y_i - x_i| \le k\}\).

The returned solution is a local optimum: no neighbour is better. It need not be the global optimum.

A local search for the KP: the swap

The worst-case analysis suggests a move: remove a selected item and insert a later one in the UP order.

  1. Run greedy UP, getting \(x\) and residual capacity \(R\); items stay sorted by UP.
  2. Scan items from 1 to \(n\): if \(x_j = 1\) and there is \(k > j\) with \(v_k \le R + v_j\) and \(p_k > p_j\), set \(x_j = 0\), \(x_k = 1\), \(R = R + v_j - v_k\).
  3. If step 2 gave no improvement, stop; otherwise repeat step 2.

Press "local search" in both widgets. On the pathological instance one swap (out 1, in 2) reaches the optimum 99. On Star Truck, instead, no single swap improves the greedy UP solution (23): it is a local optimum but not a global one (26). Reaching the optimum would take richer moves, for instance two items out and one in.

Conclusions

The Knapsack Problem is the simplest of the hard optimization problems:

  • In theory, no known algorithm solves all instances exactly in time polynomial in the input size.
  • In practice, many instances of real-world relevance are solved to optimality in short computing time.

It lies at the core of many real packing and cutting problems: loading boxes on trucks, ships or airplanes; cutting rectangular pieces from large panels of wood, glass or metal.

Next lecture: an exact method for the KP, dynamic programming.

Key takeaways

  • KP: \(\max \sum p_j x_j\) s.t. \(\sum v_j x_j \le C\), \(x_j \in \{0,1\}\); brute force tests \(2^n\) subsets.
  • A heuristic is judged on time and error; in a maximization problem \(R_A = \inf_I A(I)/OPT(I) \le 1\).
  • Greedy: a fixed order, no backtracking. Optimal only on matroids (e.g. Kruskal).
  • KP criteria: P, V, UP (best on average); yet the ratio can go to 0.
  • Improved greedy: the better of \(x^G\) and the first item left out, guarantee \(\ge 0.5\) via the linear relaxation.
  • Local search: neighborhood + move (swap); it stops at a local optimum.
