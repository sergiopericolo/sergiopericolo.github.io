Dynamic programming: rod cutting and the knapsack

Lecture 2 of Computational Methods (Carlo Filippi, University of Brescia). The heuristics of lecture 1 are fast but give no guarantee of optimality. Dynamic programming (DP) is an exact method: it breaks the problem into smaller subproblems, solves each of them only once and combines their solutions.

Roadmap:

  1. Rod cutting — the Serling Enterprises case, brute force, the recursive formula, the DP algorithm and the reconstruction of the solution.
  2. The knapsack problem — Paul Atreides' case, the subproblems \(f(g, j)\), the DP table, the reconstruction and pseudopolynomial time.

The Rod Cutting Problem (RCP)

The Serling Enterprises case

Serling Enterprises buys long steel rods of length \(n\) and cuts them into shorter rods, which it then sells.

  • Shorter rods may take any integer length \(j = 1, 2, \dots, n\).
  • A rod of length \(j\) sells at price \(p_j\).
  • Each cut is free.

What is the best way to cut a rod? This is the Rod Cutting Problem (RCP). For example, with \(n = 4\):

\(j\) 1 2 3 4
\(p_j\) 1 5 8 9

There are 8 cutting patterns:

Pattern Revenue Pattern Revenue
(4) 9 (1)(3) 1 + 8 = 9
(2)(2) 5 + 5 = 10 (3)(1) 8 + 1 = 9
(1)(1)(2) 1 + 1 + 5 = 7 (1)(2)(1) 1 + 5 + 1 = 7
(2)(1)(1) 5 + 1 + 1 = 7 (1)(1)(1)(1) 4

The best is two pieces of length 2: revenue 10.

Brute force

Let \(r_n\) be the optimal revenue for a rod of length \(n\). If the optimum cuts the rod into \(k\) pieces, \(n = i_1 + i_2 + \dots + i_k\) and \(r_n = p_{i_1} + p_{i_2} + \dots + p_{i_k}\). We could enumerate all ways of writing \(n\) as a sum of positive integers and price each one. But:

  • many partitions are equivalent (1 + 3 and 3 + 1 give the same revenue);
  • there are too many evaluations: at each of the \(n - 1\) positions we cut or not, hence \(2^{n-1}\).

A recursive formula

The search can be set as a recursion:

\[r_n = \max \{ p_n,\ r_1 + r_{n-1},\ r_2 + r_{n-2},\ \dots,\ r_{n-1} + r_1 \}\]

Once we decide where the first cut goes, the problem splits into two subproblems of the same kind, solved with the same logic down to the trivial case \(r_1\).

Optimal substructure. Optimal solutions to a problem incorporate optimal solutions to related subproblems, which can be solved independently.

An equivalent and simpler recursion only decides the length \(j\) of the first piece on the left (which is not cut further) and recurses on the rest, of length \(n - j\):

\[r_n = \max_{1 \le j \le n} \{ p_j + r_{n-j} \} = \max \{ p_1 + r_{n-1},\ p_2 + r_{n-2},\ \dots,\ p_n + r_0 \}, \qquad r_0 = 0\]

For \(n = 4\):

\[r_4 = \max \{ p_1 + r_3,\ p_2 + r_2,\ p_3 + r_1,\ p_4 + r_0 \}\]

\[r_3 = \max \{ p_1 + r_2,\ p_2 + r_1,\ p_3 + r_0 \}\]

\[r_2 = \max \{ p_1 + r_1,\ p_2 + r_0 \}, \qquad r_1 = p_1 + r_0, \qquad r_0 = 0\]

The DP trick: compute all the \(r_j\) for \(j = 0, 1, \dots, n\) in increasing order. Each subproblem is then solved only once, and when \(r_{n-j}\) is needed it is already in the table.

The algorithm and the reconstruction

The basic algorithm finds the optimal revenue but not how to cut. We need a second array \(s = [s_0, s_1, \dots, s_n]\): \(s_j\) is the length of the first piece to cut from a rod of length \(j\) to get the optimal revenue.

  1. Initialize \(r = [r_0, \dots, r_n]\) and \(s = [s_0, \dots, s_n]\); \(r_0 = 0\), \(j = 1\).
  2. Compute \(r_j = \max \{ p_1 + r_{j-1},\ p_2 + r_{j-2},\ \dots,\ p_j + r_0 \}\); let \(i\) be the index achieving the max, \(r_j = p_i + r_{j-i}\): set \(s_j = i\) and \(j = j + 1\).
  3. If \(j > n\) return \(r_n\) and \(s\); otherwise go back to step 2.

Reconstruction. With \(n = 5\) and \(s = [0, 1, 2, 3, 2, 2]\): \(s_5 = 2\), cut a piece of length 2 and a rod of length 3 remains; \(s_3 = 3\), cut a piece of length 3 and 0 remains. Done: \(5 = 2 + 3\).

The widget uses the example prices extended up to 8: (1, 5, 8, 9, 10, 17, 17, 20). Press "next" to watch each \(r_j\) grow out of the values already known; the winning candidate is highlighted. Then move \(n\) (with \(n = 5\) you find \(s = [0, 1, 2, 3, 2, 2]\)).

Running time

Almost all the work is in step 2, which for value \(j\) adds \(j\) pairs of numbers and performs a fixed number of other operations. The operations are therefore proportional to

\[1 + 2 + 3 + \dots + n = \frac{n(n+1)}{2} = O(n^2)\]

against the \(2^{n-1}\) evaluations of brute force. With \(n = 30\): 465 against more than 500 million.

The Knapsack Problem (KP)

Paul Atreides' problem

Paul Atreides must choose a few items to survive in the deadly desert of Arrakis (tent, water flask, food…). He has only a small 5-litre bag and a few minutes before the Sardaukar arrive. Each item has a volume and a survival value. How should he fill the bag?

It is a KP: items \(j = 1, \dots, n\) with value \(p_j\) and volume \(v_j\), capacity \(C\), \(x_j \in \{0, 1\}\).

\(j\) 1 2 3 4
\(p_j\) 3 4 5 6
\(v_j\) 2 3 4 5

\[\max\ 3x_1 + 4x_2 + 5x_3 + 6x_4 \quad \text{s.t.} \quad 2x_1 + 3x_2 + 4x_3 + 5x_4 \le 5, \qquad x_j \in \{0, 1\}\]

Like the RCP, the KP has an optimal substructure. The differences:

RCP KP
The "volumes" are \(v_j = j = 1, 2, \dots, n\) The \(v_j\) are arbitrary integers
Any number of pieces of length \(j\) can be cut Each item can be loaded at most once

The first difference simplifies things, the second makes them harder: remembering the residual capacity is not enough, we also need to know which items are still available.

Subproblems and recursion

Subproblems come from considering fewer items and/or a smaller capacity. For \(0 \le j \le n\) and \(0 \le g \le C\):

\[f(g, j) = \max \sum_{i=1}^{j} p_i x_i \quad \text{s.t.} \quad \sum_{i=1}^{j} v_i x_i \le g, \qquad x_i \in \{0, 1\}\]

that is, the best value using only the first \(j\) items and capacity \(g\). The original problem is \(f(C, n)\). For item \(j\) there are two options:

\[f(g, j) = \begin{cases} \max \{ p_j + f(g - v_j,\ j - 1),\ \ f(g,\ j - 1) \} & \text{if } g - v_j \ge 0 \\ f(g,\ j - 1) & \text{otherwise} \end{cases}\]

  • \(p_j + f(g - v_j, j - 1)\): item \(j\) is selected, leaving capacity \(g - v_j\) for the first \(j - 1\) items.
  • \(f(g, j - 1)\): item \(j\) is not selected.

Initial conditions: \(f(g, 0) = 0\) for every \(g\) (no items) and \(f(0, j) = 0\) for every \(j\) (no capacity).

The DP table

The computations fill a table with \((C + 1)\) rows (\(g = 0, \dots, C\)) and \((n + 1)\) columns (\(j = 0, \dots, n\)), column by column. Each cell \(f(g, j)\) reads two cells of the previous column: the one on the same row, \(f(g, j-1)\), and the one \(v_j\) rows higher, \(f(g - v_j, j - 1)\).

  1. Initialization: row 0 and column 0 set to zero; \(j = 1\), \(g = 1\).
  2. Iteration: if \(g - v_j \ge 0\), \(f(g, j) = \max \{ p_j + f(g - v_j, j - 1),\ f(g, j - 1) \}\), and if the first term wins mark the cell; otherwise \(f(g, j) = f(g, j - 1)\). Then \(g = g + 1\).
  3. End of column: if \(g \le C\) go back to step 2; otherwise \(j = j + 1\).
  4. End of table: if \(j \le n\) set \(g = 1\) and go back to step 2; otherwise return \(f(C, n)\).

A marked cell says: "in this subproblem item \(j\) is in the solution".

Reconstruction. The bottom-right corner holds the optimal value. To know which items to load, start there and follow the marks:

  1. \(g = C\), \(j = n\), \(S = \emptyset\).
  2. If \(g = 0\) or \(j = 0\), return \(S\).
  3. If \(f(g, j)\) is marked: \(S = S \cup \{j\}\) and \(g = g - v_j\).
  4. \(j = j - 1\) and go back to step 6.

Running time: pseudopolynomial

  • Step 1: creates a table with \((C + 1)(n + 1)\) cells.
  • Steps 2–4: a fixed number of operations for each of the \(n \cdot C\) cells.
  • Steps 5–8: a fixed number of operations at most \(n + C\) times.

In total \(O(nC)\). It looks polynomial, but it is not polynomial in the input size: writing the number \(C\) takes about \(\log_2 C\) binary digits, and \(C = 2^{\log_2 C}\) grows exponentially in them. Doubling the digits of \(C\) squares the work. This is pseudopolynomial time: great when \(C\) is small, hopeless when \(C\) is huge.

A useful side effect. By construction, solving a KP with \(n\) items and capacity \(C\) solves all instances with the first \(j\) items and capacity \(g\), for every \(0 \le j \le n\) and \(0 \le g \le C\): the last column tells at once, for instance, what to do with a 4-litre bag.

Conclusions

  • Solving a KP with \(n\) items and capacity \(C\) by DP requires a matrix with \(C + 1\) rows and \(n + 1\) columns and a constant number of operations per cell: \(O(nC)\), pseudopolynomial.
  • The KP remains computationally hard in general, which explains the importance of heuristic approaches.
  • Dynamic programming is a general algorithmic idea that applies to many problems, including stochastic ones.

Key takeaways

  • Optimal substructure: the optimum of a problem contains optima of subproblems.
  • DP computes each subproblem only once, in an order where the subproblems it needs are already solved.
  • RCP: \(r_n = \max_{1 \le j \le n} \{ p_j + r_{n-j} \}\), \(r_0 = 0\); \(O(n^2)\) against \(2^{n-1}\); the array \(s\) rebuilds the cuts.
  • KP: \(f(g, j) = \max \{ p_j + f(g - v_j, j - 1),\ f(g, j - 1) \}\); a \((C+1) \times (n+1)\) table; the marks rebuild the solution.
  • \(O(nC)\) is pseudopolynomial: polynomial in the value of \(C\), exponential in its length in bits.
